## 1. Target architecture

```
client/ (React 19 + TS 6 + Vite 8 + Tailwind 4 + shadcn/ui)
  src/app            router, providers (QueryClient, Auth, Theme)
  src/components     ui/ (shadcn), common/, tables/, forms/, modals/, charts/, documents/
  src/layouts        MainLayout (rail + main), AuthLayout, ProtectedRoute, RequirePermission
  src/modules/<m>    pages/, components/, services/ (axios calls), hooks/ (TanStack Query), types/, schemas/ (zod)
  src/services/api.ts  axios instance: in-memory access token, 401 → refresh (single-flight) → retry
  src/lib            format (inr, fmtD), calc preview (mirror of server rules), csv helpers

server/ (Java 17, Spring Boot 4.1, Maven) com.iotiq.partnererp
  common/       ApiResponse, PageResponse, errors (ProblemDetail), Money, BusinessCalendar (addBiz, FY), validation
  config/       Security, Cors, OpenApi, Jpa auditing, Clock (Asia/Kolkata), Jackson (BigDecimal as string)
  security/     JWT, refresh tokens, permission evaluator, PartnerScope
  modules/      auth, users, settings, partners, leads, products, estimates, invoices, b2c, payments, payouts, dashboard, reports, audit
     each: controller → service (transactions, rules) → repository (Spring Data) ; entity ; dto ; mapper (MapStruct)
  resources/db/migration  Flyway V1..V11

prd/  docker-compose.yml, nginx/ (TLS reverse proxy, SPA + /api), .env.example, backup scripts, runbooks
```

Key cross-cutting components:
- **`DocumentCalculator`**: the Java port of `totals()` with BigDecimal. One implementation is used by estimates, invoices and twins.
- **`InvoiceStatusResolver`**: `invStatus`. **`LeadSlaCalculator`**: `leadSla`. **`TierPolicy`**: `tierForRev`, `reviewCp`. **`TdsCalculator`**: `tdsFor`. **`BusinessCalendar`**: `addBiz`, `addDays`, `fyOf`, `fyTag`.
- **`AlertService`**: the 7 alert rules, shared by the dashboard badge and the alerts panel.
- **Golden vectors:** `server/src/test/resources/golden/*.json`, generated by running the original JS helpers in Node from `docs/reference`. Vitest reuses them for the TS preview.

## 2. Phase checklist

### Phase 1: Backend foundation
- `pom.xml`: Java 17, Spring Boot 4.1.1, web, validation, data-jpa, security, actuator, flyway-core + flyway-database-postgresql, postgresql, springdoc-openapi, jjwt (or Nimbus), mapstruct, lombok (optional), test: spring-boot-starter-test, spring-security-test, testcontainers-postgresql.
- `application.yml` + `-dev`/`-test`/`-prd` profiles; all secrets from env (`DB_URL`, `DB_USER`, `DB_PASSWORD`, `JWT_SECRET`, `CORS_ORIGINS`).
- GlobalExceptionHandler (ProblemDetail + envelope), validation messages, request-id filter, JSON logging (logback, prd profile), CORS allowlist, OpenAPI config, actuator health (db), `Clock` bean.
- Security baseline: everything denied except `/actuator/health`, `/v3/api-docs` (dev only), `/api/v1/auth/**` (stubbed until Phase 3).
- Flyway V1 only (extensions).
- **Accept:** `mvn -B verify` passes; app starts on dev profile; DB connect; Flyway applied; `/actuator/health` = UP.

### Phase 2: Schema & seed
- Migrations V2–V11 (DATABASE_DESIGN §6). Delete the 9 empty placeholder migrations (ADR-03).
- JPA entities and repositories for all tables. Converters for enums.
- Seeds: 4 tiers, settings defaults (BUSINESS_RULES §2), 29 products (idempotent), roles + permissions.
- Testcontainers tests: migrations apply from empty; 29 products, category counts 6/14/4/5, Σ partner price 344094, all B2C prices NULL; 4 tiers; FK/unique/check constraints reject bad rows (dup SKU case-insensitive, twin with both parents, payout duplicate per payment).
- **Accept:** as prompt.

### Phase 3: Authentication & authorization
- User/Role/Permission entities, BCrypt, login, refresh rotation with reuse detection, logout, `/auth/me`, change password, lockout after N failures.
- Bootstrap SUPER_ADMIN from env (`ADMIN_EMAIL`, `ADMIN_INITIAL_PASSWORD`, forced change on first login). No hard-coded password.
- Method security + permission evaluator + PartnerScope skeleton.
- Frontend: login page, AuthContext (memory token), axios refresh interceptor, ProtectedRoute, RequirePermission.
- Tests: login ok/fail, expired token 401, refresh rotation, reuse → revoke, role-forbidden 403 matrix spot checks.

### Phase 4: Frontend foundation
- Dependencies, shadcn init (`components.json`, `@/*` paths), theme tokens from the source CSS, fonts, light/dark/system toggle (D-20).
- MainLayout: 216 px forest rail with groups, alert badge, footer note; ≤820 px horizontal rail; header with user menu.
- Shared components: PageHeader (title/subtitle/actions), KpiTile, DataTable (zebra, sortable, empty state), SearchInput (debounced), FilterSelect, StatusPill (good/warn/bad/info/gold), Money (₹ en-IN, mono), DateText, CurrencyInput, FormField (RHF+zod), Modal/Sheet, ConfirmDialog, Toast (sonner), LoadingState, ErrorState, ErrorBoundary.
- Routes for all 10 views (placeholders clearly labelled "not implemented yet", never fake data).
- Vitest + Testing Library + MSW harness.
- **Accept:** `npm run build`, `npm run lint`, `npm test` pass; authenticated navigation works.

### Phase 5: Partners
Backend CRUD, status patch, search/filter, revenue12m, calculated tier, performance, tier review preview/apply + history, masked PAN/bank. Frontend list, form (3 sections), detail tiles/compliance/linked tables (empty until later phases), tier review dialog. Tests: BR-P1..P13, tier review matrix (upgrade multi-step, grace → downgrade one step, recovered, programme).

### Phase 6: Leads
CRUD, conflict detection (last-10 digits, different partner, protected), acknowledge, stage change with D-04 rules + history, soft delete (D-26), SLA calculator, filters. Frontend list with inline stage select, acknowledge confirm, SLA pills, lead detail with history. Tests: SLA golden vectors (48.5 h boundary, Won/Lost exclusions, estimate earliest-date), protection boundary (`>=` today), conflict cases.

### Phase 7: Products
CRUD, deactivate, B2C fields permission-gated, CSV import (dry-run → commit, D-18 rules) / export / template. Frontend sheet with pills, discount %, category filter, import preview dialog. Tests: SKU case-insensitive uniqueness, partner-role JSON has no b2c keys, import upsert, missing-column behaviour.

### Phase 8: Estimates + B2C twin
DocumentCalculator, numbering, editor preview endpoint, create/update with twin in one transaction, status actions with lead side effects, delete rules, partner-safe vs internal DTOs, print view + PDF (partner and internal). Frontend editor (grouped product picker, lines, live totals, missing-B2C stamp, fee field gated), list, viewer with copy toggle. Tests: totals golden vectors (discount, mixed GST, rounding), twin rollback (force twin failure → no estimate row), INT- numbering, leak tests.

### Phase 9: Invoices
Create direct or from estimate, side effects (estimate INVOICED, lead WON), edit lock (D-09), cancel, derived status, balance, twin, PDF. Tests: status derivation table (6 states, ₹0.50 tolerance, due-date boundary), totals reconcile with lines, rollback.

### Phase 10: Payments
Record payment (row lock, validation per D-10, idempotency), net calc, refund, reversal (D-11), history. Tests: partial/multiple payments to Paid, overpayment rejection, duplicate key replay, refund sign, reversal guard.

### Phase 11: Payouts
Accrual in the payment transaction, clawback window from first positive payment, business-day due by tier, auto-upgrade (D-06), mark paid (PAN/bank guard, TDS suggestion), reverse payout (D-12), fee statement CSV. Tests: `addBiz` vectors (Fri→Mon etc.), TDS formula table (below, crossing, above threshold, exact equality), clawback inside/outside 90 days, one payout per payment.

### Phase 12: Dashboard & reports
KPIs, funnel, alerts (7 types), top partners, tier mix, 8 reports + CSV (+ optional filters). Reconciliation tests: dashboard figures equal report totals and raw SQL sums on a fixture dataset.

### Phase 13: Settings & administration
Company/rules/tier settings with validation and audit. Effects verified (e.g. changing `dueDays` affects new invoices only). User management, role-permission editing, password policy, audit log viewer.

### Phase 14: QA
Full E2E (Playwright): Partner → Lead → Acknowledge → Estimate → Invoice → Payment → Payout, B2C twin checks, partner-safe leak checks, responsive checks at 375/820/1280 px, error scenarios, transaction rollback tests. Fix critical defects.

### Phase 15: Production preparation
Multi-stage Dockerfiles (server: Temurin JRE 17, non-root; client: nginx serving static files), `prd/docker-compose.yml` (postgres with volume + healthcheck, server, nginx TLS), env template, JSON logs, backup (`pg_dump` cron) and restore runbook, deploy/rollback runbook. **No live deployment without approval.**
